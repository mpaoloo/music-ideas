# Eval музыкального архива

Запуск из корня проекта:

```sh
.venv/bin/python -m eval.run_eval
```

Требуется заполненный `.env`. Это настоящие платные обращения к выбранной LLM.
Сценарии заданы заранее в `cases.json`. Каждый случай начинает с одинаковой
библиотеки из пяти синтетических карточек в отдельной временной SQLite-базе.
Рабочая база, пользовательские аудио и VPS не используются и не изменяются.

Проверяются поиск по инструменту, настроению, темпу и тексту, пустые результаты,
исключение неизвестного BPM из числового диапазона, заполнение известных полей,
отсутствие выдуманных неизвестных полей, подтверждение создания и удаления,
отмена удаления и уточнение неоднозначного запроса.

Модель предлагает действие; runner имитирует отдельное подтверждение только на
тестовых данных. Отмена означает отсутствие вызова delete_idea после предложения.
Клики в браузере и диалог confirm этот eval не проверяет.

`results.json` содержит входные запросы, ожидания, ответы, trace вызовов,
проверки, время, число обращений к модели и метаданные запуска. Сохраняется
после каждого случая, поэтому частичные результаты остаются при прерывании.
`report.md` содержит разбор завершённого запуска.

Ограничения методики:

- Один прогон на сценарий, без оценки вероятности успеха на повторениях.
- Проверки по названиям и значениям полей строгие, смысловые синонимы не засчитываются.
- Для поиска проверяется набор карточек последнего успешного вызова поиска.
  Это не гарантирует точность каждого слова итогового ответа; ответы разбираются отдельно.
- Признак вопроса в уточнении — простой автоматический критерий, требуется чтение ответа.
- Нет проверки распознавания звука, нагрузки, многопользовательского доступа и браузерного интерфейса.
- Ошибки MCP и формата API дополнительно покрыты обычными тестами проекта без оплаты API.
