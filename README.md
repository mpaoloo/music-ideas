# Черновики

Веб-сервис для хранения музыкальных идей: аудиозаписи, заметки и поиск с помощью LLM.
Модель разбирает текстовые описания и вызывает инструменты музыкальной библиотеки через MCP.
Аудио хранится и воспроизводится в браузере; автоматического анализа звука нет.

## Возможности

- Создание карточки вручную или предложение полей по тексту через AI.
- Подтверждение и редактирование предложенных полей перед сохранением.
- Загрузка MP3, WAV, M4A и OGG до 20 МБ.
- Поиск по словам или запросу к AI с фильтрами инструмента, настроения и BPM.
- Просмотр вызовов инструментов при работе AI-помощника.

## Запуск локально

Проверено на Python 3.12, macOS и Ubuntu 24.04.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Открой http://127.0.0.1:8000. Библиотека и ручное добавление работают без LLM.
Для помощника заполни `.env` и перезапусти сервер:

```dotenv
LLM_API_KEY=your-api-key
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-6.1-terra
```

Ключ, база и пользовательские аудиозаписи не включены в репозиторий.
Для gpt-6.1-terra используется Responses API, reasoning.effort=none, лимит ответа 1500 токенов.
Для других Model ID пока используется Chat Completions; совместимость нужно проверять отдельно.
Текст запроса и результаты инструментов передаются провайдеру модели. Аудио модели не отправляется.

## Как работает запрос

1. Веб-приложение получает от MCP-сервера названия, описания и схемы инструментов.
2. Передаёт их вместе с запросом пользователя в LLM.
3. Проверяет предложенные моделью параметры по JSON Schema.
4. Выполняет чтение через MCP и возвращает модели результат для ответа.
5. Если модель предложила создание карточки, показывает поля пользователю.
   Запись происходит после отдельного подтверждения в форме.

MCP-клиент находится в приложении. MCP-сервер запускается отдельным процессом
на той же машине и общается с ним через stdio. Сам сервер модель не запускает.
На каждый веб-запрос к библиотеке открывается отдельная MCP-сессия.
Данные хранятся в SQLite (`data/ideas.sqlite3`), аудио — в `uploads/`.

### MCP-инструменты

- `create_idea`: сохраняет название, описание, инструмент, настроение, BPM, теги и путь к файлу.
- `get_idea`: получает карточку по ID или возвращает found=false.
- `search_ideas`: ищет по подстроке и фильтрам. Все фильтры применяются одновременно,
  границы BPM включаются; неизвестный BPM не подходит под диапазон.

Инструмент и настроение сравниваются целиком без учёта регистра.
Текст ищется в названии, описании и тегах. Для небольшой библиотеки
фильтрация выполняется в Python после чтения карточек из SQLite.

## Структура

```text
app/main.py             HTTP-маршруты, аудио и веб-интерфейс
app/static/index.html   интерфейс на HTML/CSS/JavaScript
app/agent.py            цикл LLM и вызова MCP-инструментов
app/llm.py              HTTP-клиент модели
app/mcp_client.py       запуск и подключение MCP-сервера
mcp_server/server.py    MCP-инструменты
mcp_server/storage.py   карточки и SQLite
tests/                 автоматические проверки
eval/                  результаты первой проверки модели
deploy/                файлы развёртывания
```

## Проверки

```sh
.venv/bin/python -m unittest discover -s tests -v
```

14 тестов проверяют сохранность данных, фильтры, ошибки, настоящий обмен MCP через
отдельный процесс, ожидание подтверждения, лимит цикла, HTTP-формат API модели,
загрузку аудио, диапазонную выдачу для плеера и ошибку конфигурации LLM.
Тесты используют временные базы и заданные ответы модели; платных API-запросов нет.

Первая проверка настоящей модели: [eval/smoke-results.md](eval/smoke-results.md).
Это три примера, а не полный eval или гарантия стабильности модели.

## Развёртывание

Инструкция: [deploy/README.md](deploy/README.md).
Подготовленная служба systemd слушает 127.0.0.1:8000, перезапускается при сбое
и ограничена 512 МБ памяти и 60% одного CPU. Для данного VPS HTTPS предоставляет
Caddy на порту 8443, не затрагивая Xray на 443. Пароль демо хранится отдельно
и не публикуется. Перед использованием deploy-скриптов на другом сервере
адаптируй пользователя, пути, имя сайта и порты.

## Ограничения

- Одна общая библиотека. Отдельных аккаунтов и разделения записей по владельцам нет.
- Постоянного инструмента удаления и редактирования существующих записей пока нет.
- Нет семантического поиска, автоматического определения BPM или тональности по звуку.
- Каждый AI-запрос независимый: истории диалога нет.
- Модель может ошибаться в выборе фильтров. Неизвестные параметры следует оставлять пустыми.
- Лимит на один запрос: четыре вызова инструментов, максимум пять обращений к модели.
- Формат аудио проверяется по расширению, пустоте и размеру, без перекодирования.
- Загруженный, но не сохранённый в карточку файл пока остаётся на диске.
- Подтверждение создания обеспечивает приложение; прямой MCP-клиент может вызвать создание самостоятельно.
- Ограничений расходов API и нагрузки на уровне приложения пока нет.
