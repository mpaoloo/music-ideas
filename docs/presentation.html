25 секунд. Я музыкант и выбрал близкую мне задачу: хранение музыкальных идей. Результат проекта — веб-приложение «Черновики». В нём можно сохранять короткие записи с заметками, а затем искать их обычным текстовым запросом. Сервис размещён на VPS и доступен по ссылке. Сегодня покажу основной сценарий, устройство системы и результаты проверки.
Задача и границы

Найти нужную идею среди записей

  • Риффы и мелодии копятся в файлах с непонятными названиями.
  • Для поиска важны инструмент, настроение, темп и заметки.
  • Пользователь первой версии — музыкант с личным архивом.
«Где тот спокойный гитарный набросок для куплета?»

В первой версии одна общая библиотека. Разделения по аккаунтам нет.

45 секунд. Когда появляется музыкальная идея, хочется быстро её записать и продолжить работу. Со временем остаются десятки файлов, а контекст забывается: для какой части трека это было, какой инструмент, что хотелось попробовать дальше. Поэтому я ограничил задачу архивом коротких записей с метаданными. Пользователь может добавить информацию вручную или описать её помощнику. Я не делал редактор музыки, совместную работу или полноценную систему аккаунтов. Это позволяет показать законченный сценарий в небольшом проекте.
Основной сценарий

Сохранение и поиск наброска

  1. Добавить аудио и описание музыкальной идеи.
  2. Проверить предложенные AI поля и подтвердить сохранение.
  3. Найти запись по запросу и прослушать её в браузере.
«Найди гитарные идеи от 90 до 110 BPM»

Настроение и BPM берутся из описания пользователя. Модель не анализирует аудио.

50 секунд. Например, я описываю мрачный гитарный рифф, указываю 95 BPM и идею для куплета. Помощник предлагает название и поля карточки. Я могу их исправить и только затем сохранить вместе с аудио. Когда хочу вернуться к записи, формулирую запрос по инструменту или темпу. Обычный поиск по словам также доступен. Важно: модель работает с текстом. Если темп или настроение неизвестны, соответствующие поля должны остаться пустыми. Автоматическое определение характеристик по звуку не входит в текущую версию.
Устройство системы

Браузер, приложение, модель и MCP

LLM предлагает действие. Код проверяет параметры и выполняет вызов через MCP.

75 секунд. Интерфейс работает в браузере. На VPS Caddy принимает HTTPS и проверяет общий пароль демо, затем передаёт запрос Python-приложению на внутреннем порту. Модель находится у OpenAI, на нашем VPS она не развёрнута. Приложение передаёт ей текст и описания доступных инструментов. Когда модель предлагает вызов, приложение проверяет параметры и отправляет запрос MCP-серверу. Он запускается отдельным процессом на той же машине и общается с клиентом через stdio. Карточки хранятся в SQLite, а аудиофайлы приложение хранит и отдаёт отдельно. Результат инструмента возвращается модели, чтобы она составила ответ. Ключ API находится на сервере, в браузер и репозиторий он не попадает.
Интеграция MCP

Четыре инструмента библиотеки

create_idea сохранить карточку
search_ideas найти по тексту и фильтрам
get_idea получить карточку по ID
delete_idea удалить одну карточку

Создание и удаление в веб-приложении требуют подтверждения пользователя.

Для одного приложения хватило бы прямого доступа к базе. MCP выбран по требованиям проекта и предоставляет стандартный интерфейс инструментов.

50 секунд. MCP-сервер предоставляет четыре инструмента. Клиент получает их описания и схемы параметров, поэтому модель может предложить подходящий вызов. Поиск и чтение выполняются сразу. Создание и удаление возвращаются в интерфейс как предложение: действие выполняется после подтверждения пользователя. Подтверждение обеспечивает именно наше приложение, не сам протокол MCP. Для одного небольшого сервиса прямые вызовы базы были бы проще. Здесь я использую MCP по требованиям проекта и выделяю библиотеку в стандартный интерфейс инструментов. Его можно подключать к другим совместимым клиентам, хотя в текущем демо используется наш веб-клиент.

70 секунд, включая переключение на приложение. Здесь я покажу рабочий сценарий. Сначала открываю библиотеку и запускаю короткую запись. Важно заранее проверить, что на VPS применена версия с удалением, и войти в демо до начала выступления. Если запрос занимает слишком долго, показываю уже подготовленный результат и продолжаю.
Результат и ограничения

Работающий архив с AI-помощником

  • Веб-сервис размещён на VPS, код и инструкция опубликованы.
  • LLM участвует в сохранении и поиске через MCP-инструменты.
  • Аудио не анализируется; отдельные аккаунты и история диалога не реализованы.

Следующие шаги: личные библиотеки пользователей, редактирование карточек, расширение eval.
